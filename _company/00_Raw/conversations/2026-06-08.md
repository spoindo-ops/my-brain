*   **핵심 리스크:** AI 학습에 사용된 개인 식별 정보(PII)가 컴플라이언스를 위반했을 경우 발생하는 막대한 과징금 및 법적 소송 비용.
*   **정량화된 위험 지표 1 (최대 벌금):** **$20M ~ $35M+** (GDPR 최대 매출액 대비 비율 적용 시 더욱 충격적).

*   **정량화된 위험 지표 2 (운영 중단):** **최대 1년 이상의 서비스 중단 강제 명령.**

### 2. 원료 및 공급망 투명성 부족 (Provenance Failure)
*   **핵심 리스크:** 모든 핵심 성분에 대한 '데이터 증명'이 불가능해지면서, 시장 진입 자체가 법적/경제적으로 차단되는 위험. (이는 물리적 재고의 손실보다 더 큰 위협입니다.)
*   **정량화된 위험 지표 3 (시장 접근성):** **특정 국가 시장 진입 시 '필수 인증' 실패로 인한 최소 6개월 ~ 1년 지연.**
    *   [근거: Self-RAG - [2026-06-03] 시장 진입 시간 단축 | 데이터 증명 수준 요구]
*   **Designer 적용 가이드:** '붕괴 그래프'가 단순히 값이 떨어지는 것이 아니라, **공급망 다이어그램 상의 특정 노드(Node)**가 연결되어 있다가 갑자기 빛을 잃고 사라지면서 (Connectivity Loss), 그 결과로 시장 전체의 흐름이 정지하는 모션으로 구현해야 합니다.

### 3. 데이터 자산 가치 하락 (Intangible Capital Erosion)
*   **핵심 리스크:** 규제를 준수하기 위해 쌓아온 '신뢰(Trust)'가 경쟁사나 기술 변화로 인해 무용지물이 되는 상황.
*   **정량화된 위험 지표 4 (비즈니스 가치):** **평균 10% 이상의 프리미엄 가격 결정력 상실.**
    *   [근거: Self-RAG - [2026-06-03]가치 증대 (브랜드 프리미엄) | 소비자 선호도 조사]
*   **Designer 적용 가이드:** '위험 경고 게이지'를 단순히 수치가 아닌, **'자산의 공신력 레벨(Credibility Level)'**로 변경하고, 이 레벨이 하락할 때마다 배경의 톤과 색상 팔레트가 점진적으로 어둡게 변하는 (Dampening Effect) 방식으로 구현합니다.

### 🐍 백엔드 로직 구현 (risk_backend/main.py)

시간 경과에 따른 데이터 하락 및 임계점 위반을 담당하는 FastAPI 엔드포인트를 만듭니다. 이 코드는 기존의 `overall_score` 계산 로직을 확장하여, 시간이 지남에 따라 리스크가 비선형적으로 증가(혹은 감소)하는 시뮬레이션을 반영합니다.

<create_file path="./risk_index_poc/risk_backend/main.py">
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel
import time
import random
from typing import List

app = FastAPI()

# 1. 데이터 입력 스키마 정의 (핵심 안정성 요건)
class RiskDataInput(BaseModel):
    material_id: str # 필수 필드
    timestamp: float = time.time() # 시간 정보 필수
    initial_score: float # 초기 리스크 점수
    decay_rate_factor: float = 0.95 # 시간이 지남에 따른 감쇠 계수 (예: 0.95)
    threshold_breach_severity: float = 1.2 # 임계점 위반 시 가중치

# 2. PoC 핵심 로직 함수
def calculate_risk(data: RiskDataInput) -> dict:
    """
    시간 경과에 따른 리스크 점수 계산 및 임계점 위반 여부를 결정합니다.
    """
    current_score = data.initial_score * (data.decay_rate_factor ** (time.time() - data.timestamp))

    # 2-1. 시간 기반 데이터 하락 시뮬레이션
    simulated_score = current_score * random.uniform(0.9, 1.1) # 노이즈 추가
    
    # 2-2. 임계점 위반 로직 (Nonlinear Trigger)
    breach_multiplier = 1.0
    warning_status = "NORMAL"
    
    if simulated_score > 50: # 가상의 임계점 (Threshold Breach Point)
        breach_multiplier = data.threshold_breach_severity
        simulated_score *= breach_multiplier # 비선형적 스파이크 발생
        warning_status = "CRITICAL"
    elif simulated_score > 30:
        breach_multiplier = 1.2
        simulated_score *= breach_multiplier
        warning_status = "HIGH"

    # 최종 결과 포맷팅
    return {
        "timestamp": time.strftime("%Y-%m-%d %H:%M:%S", time.localtime(data.timestamp)),
        "initial_score": round(data.initial_score, 2),
        "decayed_score": round(current_score, 2),
        "final_risk_index": round(simulated_score, 2), # 최종 점수
        "warning_status": warning_status,             # 경고 상태 (CRITICAL/HIGH/NORMAL)
        "breach_multiplier_applied": breach_multiplier  # 적용된 가중치
    }

@app.post("/calculate_risk")
async def calculate(data: RiskDataInput):
    """리스트 데이터 수신 및 리스크 계산 API 엔드포인트."""
    try:
        result = calculate_risk(data)
        return {"status": "success", "data": result}
    except Exception as e:
        print(f"Error during calculation: {e}")
        raise HTTPException(status_code=500, detail="Internal Server Error during risk calculation.")

# 테스트용 시작 메시지 (실제 사용 시에는 제외)
@app.get("/")
async def root():
    return {"message": "Risk Index PoC Backend operational. Use POST /calculate_risk."}

### 🐍 백엔드 로직 구현 (risk_backend/main.py)

시간 경과에 따른 데이터 하락 및 임계점 위반을 담당하는 FastAPI 엔드포인트를 만듭니다. 이 코드는 기존의 `overall_score` 계산 로직을 확장하여, 시간이 지남에 따라 리스크가 비선형적으로 증가(혹은 감소)하는 시뮬레이션을 반영합니다.

<create_file path="./risk_index_poc/risk_backend/main.py">
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel
import time
import random
from typing import List

app = FastAPI()

# 1. 데이터 입력 스키마 정의 (핵심 안정성 요건)
class RiskDataInput(BaseModel):
    material_id: str # 필수 필드
    timestamp: float = time.time() # 시간 정보 필수
    initial_score: float # 초기 리스크 점수
    decay_rate_factor: float = 0.95 # 시간이 지남에 따른 감쇠 계수 (예: 0.95)
    threshold_breach_severity: float = 1.2 # 임계점 위반 시 가중치

# 2. PoC 핵심 로직 함수
def calculate_risk(data: RiskDataInput) -> dict:
    """
    시간 경과에 따른 리스크 점수 계산 및 임계점 위반 여부를 결정합니다.
    """
    current_score = data.initial_score * (data.decay_rate_factor ** (time.time() - data.timestamp))

    # 2-1. 시간 기반 데이터 하락 시뮬레이션
    simulated_score = current_score * random.uniform(0.9, 1.1) # 노이즈 추가
    
    # 2-2. 임계점 위반 로직 (Nonlinear Trigger)
    breach_multiplier = 1.0
    warning_status = "NORMAL"
    
    if simulated_score > 50: # 가상의 임계점 (Threshold Breach Point)
        breach_multiplier = data.threshold_breach_severity
        simulated_score *= breach_multiplier # 비선형적 스파이크 발생
        warning_status = "CRITICAL"
    elif simulated_score > 30:
        breach_multiplier = 1.2
        simulated_score *= breach_multiplier
        warning_status = "HIGH"

    # 최종 결과 포맷팅
    return {
        "timestamp": time.strftime("%Y-%m-%d %H:%M:%S", time.localtime(data.timestamp)),
        "initial_score": round(data.initial_score, 2),
        "decayed_score": round(current_score, 2),
        "final_risk_index": round(simulated_score, 2), # 최종 점수
        "warning_status": warning_status,             # 경고 상태 (CRITICAL/HIGH/NORMAL)
        "breach_multiplier_applied": breach_multiplier  # 적용된 가중치
    }

@app.post("/calculate_risk")
async def calculate(data: RiskDataInput):
    """리스트 데이터 수신 및 리스크 계산 API 엔드포인트."""
    try:
        result = calculate_risk(data)
        return {"status": "success", "data": result}
    except Exception as e:
        print(f"Error during calculation: {e}")
        raise HTTPException(status_code=500, detail="Internal Server Error during risk calculation.")

# 테스트용 시작 메시지 (실제 사용 시에는 제외)
@app.get("/")
async def root():
    return {"message": "Risk Index PoC Backend operational. Use POST /calculate_risk."}

| 요소 | 기술 사양 (SVG/Vector) | 애니메이션 로직 (Interaction Logic) | 개발 가이드라인 |

## III. 애니메이션 모듈 컴포넌트 표준 및 트랜지션 가이드 (Animation & Transition Guide)

모든 시각적 변화는 '우연한 점프(Jump Cut)'를 피하고, 데이터 기반의 **'진화하는 위협감'**을 연출해야 합니다.

### 1. 애니메이션 공통 원칙
*   **전환 금지:** 모든 수치 및 값의 변화는 절대로 Jump Cut이어서는 안 됩니다. 반드시 이전 값 $\rightarrow$ 새 값으로 부드럽게 **카운트업/다운(Interpolation)** 트랜지션 로직을 적용해야 합니다. [근거: Designer 개인 메모리]
*   **위기감 연출:** 경고 상태 게이지의 초기 상승은 `Ease-Out` 곡선(속도 감속)을 적용하여 '점프'가 아닌 **점진적 불안감의 축적**처럼 보이게 합니다. [근거: Designer 개인 메모리]

### 2. 컴포넌트별 표준 동작 정의 (Technical Spec V4.0 준수)

| 컴포넌트 | 시각화 목표 | 트랜지션 로직 및 애니메이션 스펙 | 트리거 이벤트 |
| :--- | :--- | :--- | :--- |
| **붕괴 그래프** (Collapse Graph) | 시스템적 위협의 비가역적 붕괴. | **Multi-Stage Glitch + Decay:** 데이터 포인트를 구성하는 RGB 채널을 3~4회 반복 변위(Glitch)시키며 노이즈를 발생시킨 후, 최종적으로 선형적인 급락 곡선과 함께 투명도가 점진적으로 사라집니다 (Opacity Fade). | 리스크 지표가 임계점(Threshold)에 도달하는 순간. |
| **위험 경고 게이지** (Gauge Drop) | 통제력 상실 및 위험도 증가. | **Ease-Out 상승 곡선:** 0초부터 시작하여 `Ease-Out`을 거쳐 점진적으로 바가 상승합니다. 임계점 초과 시, 배경색이 Deep Navy에서 Critical Red로 즉각 전환되며 주기적인 Opacity 깜빡임(Flashing) 효과를 추가합니다. | 측정된 지표 값이 특정 위험 레벨을 넘어서는 순간. |
| **리스크 인덱스** (Risk Index) | 통합 리스크 수준의 정량화. | **Smooth Interpolation + Highlight:** 전체 인덱스는 Deep Navy 배경 위에서 Royal Gold로 표시되며, 수치 변화 시 카운트업이 적용됩니다. 위험성이 증가하면 해당 숫자의 텍스트 색상이 Amber $\rightarrow$ Critical Red 순으로 점진적 그라데이션 변색(Gradient Shift)을 거칩니다. | 주기적인 데이터 업데이트 (예: 매분). |

## IV. 로고 및 리스크 인덱스 배치 규칙 (Placement Rules)

### 1. 로고 배치 (Logo Placement)
*   **위치:** 화면의 우측 상단 또는 좌하단 구석에 고정적으로 배치합니다. 시청자의 시선이 콘텐츠 자체(데이터, 그래프)에 집중되도록 최소한의 공간 점유율을 유지해야 합니다. [근거: Designer 개인 메모리]
*   **규칙:** 로고는 Deep Navy 배경 위에서 **Royal Gold 단색 버전**으로만 사용합니다. Critical Red가 필요한 장면에서는 로고를 일시적으로 축소하거나 흐릿하게 처리하여 시선이 위험 경고에 집중되도록 유도합니다.

### 2. 리스크 인덱스 배치 (Risk Index Placement)
*   **핵심 역할:** 모든 콘텐츠에서 '현재 상황'을 즉각적으로 보여주는 **앵커(Anchor)** 역할을 합니다.
*   **배치:** 화면의 시청자가 가장 먼저, 그리고 마지막에 보게 되는 구역(예: 하단 1/4 지점)에 항상 고정되어야 하며, 모든 애니메이션이 이 인덱스를 향해 수렴하는 구조를 가져야 합니다.

from fastapi import FastAPI, HTTPException
from pydantic import BaseModel
import time
import random

# --- 1. 데이터 스키마 정의 (V4.0 기반) ---
class RiskScore(BaseModel):
    """시간 경과에 따른 리스크 지표를 담는 구조체."""
    timestamp: float = time.time()
    overall_score: int # 0 ~ 100
    global_risk_level: str # LOW, MEDIUM, HIGH, CRITICAL
    warning_details: dict # {key: "value", ...}

app = FastAPI(title="V4.0 Risk Gateway API")

# --- 2. Core 로직 (가장 중요한 부분) ---
def calculate_risk_score(current_time: float) -> RiskScore:
    """
    시간 흐름에 따라 리스크 점수를 계산하고 상태를 업데이트하는 핵심 비즈니스 로직입니다.
    (PoC 단계이므로 단순 시뮬레이션 사용)
    """
    # 시간 기반 변화 모방 (Ease-Out/점진적 상승 곡선 흉내)
    # 실제로는 데이터 파이프라인에서 이 값을 받아야 함.
    base_score = random.randint(20, 70) # 초기 점수 범위 설정

    # 시뮬레이션: 시간이 지날수록 위험도가 높아지는 경향을 강제 적용
    time_factor = (current_time - START_TIME) / 60.0  # 시간 변화에 따른 가중치 증가 (분 단위 가정)
    score_increase = min(25, int(time_factor * 3))

    overall_score = base_score + score_increase
    global_risk_level = "LOW"

    if overall_score >= 80:
        global_risk_level = "CRITICAL" # 임계점 도달 트리거
    elif overall_score >= 65:
        global_risk_level = "HIGH"
    elif overall_score >= 30:
        global_risk_level = "MEDIUM"

    return RiskScore(
        timestamp=current_time,
        overall_score=min(100, overall_score), # 상한선 제한
        global_risk_level=global_risk_level,
        warning_details={
            "chemical": f"{random.uniform(0.5, 1.2):.2f}x",
            "geographical": "Moderate Concern",
            "anomaly_detected": overall_score >= 80 # Critical 조건 만족 시 플래그
        }
    )

START_TIME = time.time() # PoC 시작 시간 기록

# --- 3. API 엔드포인트 정의 ---
@app.get("/api/v4/risk-status", response_model=RiskScore)
async def get_risk_status():
    """현재 시점의 리스크 상태를 반환합니다. 프론트엔드의 Polling 대상으로 사용됩니다."""
    try:
        score = calculate_risk_score(time.time())
        return score
    except Exception as e:
        print(f"Error calculating risk status: {e}")
        raise HTTPException(status_code=500, detail="Internal Server Error during calculation.")

# 테스트용 루트 엔드포인트 추가 (간단한 확인)
@app.get("/")
async def root():
    return {"message": "V4.0 Risk Gateway API operational. Use /api/v4/risk-status"}

    return () => clearInterval(intervalId);

        <h1>⚙️ V4.0 Risk Threshold Monitor</h1>

                    <h2>Overall Score: {riskData.overall_score}%</h2>
                    <p>Status: <strong>{riskData.global_risk_level}</strong></p>

                </div>

                <h3>Detailed Risk Breakdown (V4.0 Modules)</h3>
                <div className="detail-grid">
                    {/* 컴포넌트 A: 위험 경고 게이지 시스템 (시뮬레이션 영역) */}
                    <div className="module-card">
                        <h4>📈 Gauge System</h4>
                        <p>Score: {riskData.overall_score}% | Level: {riskData.global_risk_level}</p>
                        <small>(시간 경과에 따라 점진적으로 변화합니다.)</small>
                    </div>

                    {/* 컴포넌트 B & C: 추가 위험 요인 */}
                    <div className="module-card">
                        <h4>🧪 Chemical Risk</h4>
                        <p>{riskData.warning_details.chemical}</p>
                    </div>
                     <div className="module-card">
                        <h4>🌍 Geographical Risk</h4>
                        <p>{riskData.warning_details.geographical}</p>
                    </div>
                </div>

            </>
        ) : (
             <div style={{color: 'red'}}>데이터를 불러오는 데 실패했습니다. 백엔드 로그를 확인하세요.</div>
        )}
    </div>
  );
}
